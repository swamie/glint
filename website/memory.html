IMemory

Where a clipper's memory goes, and why Glint keeps so little of it.

An instant-replay clipper holds the last minutes of your game somewhere. Most of its memory is that footage, the encoder that makes it, and the window you look at it through. Here is what Glint does with each, with figures we measured and a calculator for your own settings.

IIIHow

The choices that keep it small.

  1. Recent seconds in RAM, the rest on disk

    By default only the newest 30 seconds stay in RAM (15 seconds to 2 minutes, your choice). Everything older goes to temporary files in 64 MB pieces, deleted as the buffer moves past them. A clip up to the RAM length is saved straight from RAM.

  2. No browser engine in the background

    Glint's window is drawn by WebView2, the engine Windows already has. When you close the window, Glint destroys it, so the interface costs nothing while you play. The recorder is a small native program written in Rust.

  3. A still screen costs almost nothing

    Glint never makes up duplicate frames. When the picture does not change, nothing new is encoded, and silent audio is not written at all.

  4. The graphics card does the work

    Video is encoded by NVENC, AMF or Quick Sync, so the buffer holds compressed video, never raw frames. Without a hardware encoder Glint falls back to the processor, and the log says so.

VICheck it

Measure it on your own PC.

Numbers from someone else's computer only go so far. Compare clippers with the same settings, on your machine.

  1. Match the settingsSame resolution, frame rate, bitrate and buffer length in each clipper.
  2. Play for ten minutesA buffer fills over its length. Measure once it is full, in the same game.
  3. Open Task Manager, DetailsRight-click a column header, Select columns, tick Memory (private working set).
  4. Add up every processCount the clipper's helpers and encoder too. Glint's status bar shows its own total, buffer included.
